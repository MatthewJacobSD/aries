Tasks

A task is a clear piece of work with an owner, a status, and enough context to act on it. Keep it attached to the campaign, creator, or client it belongs to, so the desk can see what needs attention without searching across separate lists.

On the task

Enough context to pick it up.

Owner

Who is responsible

Every task has a clear owner. Responsibility is visible at a glance, while changes remain part of the task history rather than disappearing into chat.

Due

When it matters

A useful due date turns an open item into something the desk can prioritise. Upcoming work stays visible without forcing every task into the same urgency.

Context

Where the work belongs

Attach the task to the campaign, creator, or client it concerns. "Confirm the payout rail" should open in the right room, with the right context already there.

How work moves

A small workflow with no hidden states.

Create from the work

Start a task from the campaign, creator, or client it belongs to. The relevant context comes with it, so the task does not become another disconnected note.

Assign the work

Give the task one accountable owner. Other people can contribute, but responsibility should remain clear.

Mark what is blocking it

If progress stops, record why. A missing form, unanswered client message, or pending approval is useful information; an unexplained "waiting" state is not.

Close when finished

When the work is complete, close the task where it lives. The status becomes part of the record instead of requiring a second checklist or private reminder.

The morning view

See the work before it becomes urgent.

The task queue should make the next decision obvious: do it, hand it over, follow up, or leave it alone. Filter by status, owner, or due date without losing the campaign or creator behind the task.
