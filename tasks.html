Tasks

A task is a named piece of work with an owner and a date. It sits on the campaign or creator it belongs to, so the morning view is a list — not a scavenger hunt.

Open the working view What a task holds
Waiting, owned, done

On the task

Enough to pick it up without a briefing.

Owner

Who has it

Finance, desk, or onboarding. If the person changes, the history stays on the row.

Due

When it matters

This week versus parked. The overview count is this list, not a separate tracker.

Context

What it sits on

Tied to a campaign, creator, or client room so “confirm the payout rail” is never a floating note.

How work is closed

Open, blocked, or done — in language the desk already uses.

Create from the file

Open a task from the campaign or creator. It inherits the room and the people already on that work.

Assign and date it

Someone is responsible. A due date is optional but the queue is honest without one.

Block only with a reason

Waiting on a form or a client is a status, not silence.

Close on the same row

Done is recorded. Hooks can tell a board without a second checklist.
